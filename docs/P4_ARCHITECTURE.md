# MeowDeck P4 — Storage, Statistics, Audio and Offline Architecture

## Existing architecture retained

P0 public card/Mochi PNGs and manifests, P1 `src/games/meowdeck` authoritative rules, P2 UI, P3 fair AI/animation, and P2.5 Next.js App Router are retained. New code is browser-local and independent of the headless rules. This document describes a **proposed P4 implementation that has not passed a real Next.js/Chromium production regression test**.

## Save and restoration

- `src/web/storage/save-schema.ts` validates schema 1, game ID, session, all 52 card identities and their rank/suit, unique action IDs, active suit, phases, actor, public history without private drawn IDs, pending drawn-card eligibility, score and round-result consistency. Invalid and unsupported future/older versions are **rejected**, not guessed; no older live save schema existed prior to P4.
- `src/web/storage/database.ts` stores one `active` record and immutable `matches` records in IndexedDB database `meowdeck-local-v1`. A save envelope includes schema version 1, `revision`, `savedAt`, `difficulty`, `nextActionSequence`, and the complete P1 `GameState`.
- The React controller `src/web/App.tsx` writes only after successful P1 `applyAction()`, at match start, and on round/restart transitions. Writes are serialized; each storage transaction validates revision and owner; completion records are inserted once under unique `matchId=sessionId` and remove the active record **in the same transaction**.
- A separate browser tab has an owner lease and cannot silently overwrite a current owner's unexpired revision. Explicit takeover can be offered; crash recovery can require lease expiration or confirmation. Leases are not a claim of protection against malicious same-origin scripts. Browser clearing data removes all saves.
- A restored match loads its original difficulty, action sequence, full deck and score. Presentation queues reset. `round_end` can display a result without replaying ephemeral animations. `match_end` is not an active save.
- Failed IndexedDB writes are visible but never block legal gameplay. This means progress may not persist until the browser storage failure is resolved.

## Statistics

`src/web/statistics/statistics-service.ts` derives wins/losses, accurate rounds, streaks and per-difficulty rates from completed records. A session ID is the unique match primary key. `LocalGameRepository.commit()` stores a terminal record and removes the active save in the same transaction; reprocessing a terminal match cannot increment statistics twice. A stats reset clears only the `matches` store and preserves the active match.

## Settings, sound and music

`src/web/settings/settings-store.ts` uses guarded `localStorage`, schema 1, TH/EN, difficulty, system/on/off motion, separate SFX/music toggles and volumes. Preferences are loaded in a hydration-safe effect. Audio in `src/web/audio/audio-manager.ts` uses **new original synthesized** Web Audio cues and a gentle original eight-note ambient sequence, with separate volumes, gesture-based unlock, visibility suspension, deterministic event-identity deduping and safe resource cleanup. Audio cannot mutate `GameState`. Animation playback speed is intentionally deferred: changing clip speed without auditing `actionFrame=3` card-flight synchronization would risk misleading card VFX. The P0 timing manifest remains authoritative.

## Installation and offline

- `src/app/manifest.ts` defines a standalone PWA; five icons under `public/icons` are **pixel-perfect derivatives from the approved Mochi idle sprite**, generated by `scripts/create-icons.py` without modifying source art.
- `scripts/build-offline.mjs` runs **after** `next build --webpack`, reads the actual `.next/BUILD_ID` and all `.next/static` runtime assets plus approved public card/Mochi assets and icons, writes `public/offline-precache.json` and a build-marked `public/sw.js` from `scripts/sw.template.js`. The generated files are intentionally not committed; the build must publish both generated files.
- The SW install downloads the complete required set before reporting ready, and deletes its cache on failure. It serves cached `/_next/static`, card, sprite, and icon assets, and a navigation fallback to cached `/`. It avoids RSC, arbitrary routes, sensitive APIs and non-GET requests. It retains a few prior build caches to avoid breaking old tabs.
- Updates wait for explicit user approval and successful authoritative-save completion. `skipWaiting()` is invoked only after that approval; save data in IndexedDB is never cleared by SW cache cleanup.
- Install guidance for iOS Add to Home Screen and `beforeinstallprompt` only appears when appropriate.

**Deployment caution:** Generated `public/sw.js` and `public/offline-precache.json` must be included in the actual Vercel output. Because a real Next production build / Vercel deploy and an offline browser reopening test could not run in the local environment, **production offline readiness remains BLOCKED**. The presence of a service worker source file alone is not proof of offline support.

The `npm run test:offline` command uses the production Playwright server. It requires a completed `npm run build` first. Do not treat a development server as an offline-ready production build.
